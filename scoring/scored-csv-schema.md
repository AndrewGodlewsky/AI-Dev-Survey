# Scored CSV — schema

Decided in wayfinder ticket [#12](https://github.com/AndrewGodlewsky/AI-Dev-Survey/issues/12).
Grilling record: [`docs/grilling/issue-12-scored-csv-schema.md`](../docs/grilling/issue-12-scored-csv-schema.md).

The **Scored CSV** is the contract between the Scoring sheet ([#15](https://github.com/AndrewGodlewsky/AI-Dev-Survey/issues/15))
and the dashboard ([#16](https://github.com/AndrewGodlewsky/AI-Dev-Survey/issues/16)). The sheet writes it; the dashboard
reads it; nothing else needs to. Worked example: [`scored-sample.csv`](scored-sample.csv) — seven **fake** Respondents,
regenerated by `node scripts/make-sample-csv.mjs`. Its header row is the exhaustive column list.

> **This file is named, internal, and never leaves the team.** It is one row per named colleague. It does not go to the
> manager (the dashboard renders the team view — [`scoring-rules.md` §4.1](scoring-rules.md)), and it is never committed:
> `.gitignore` excludes `scoring/*.csv` and re-includes only the sample.

---

## 1. Shape

**Wide.** One row per Respondent who submitted; one column per value. ~280 columns.

- The Scoring sheet's scored sheet *is* the export — one formula per cell, saved as CSV. No reshaping layer.
- The dashboard resolves every column **by header text, never by position** (the same rule [#10](https://github.com/AndrewGodlewsky/AI-Dev-Survey/issues/10) imposed on the Forms export).
- A Respondent who did not submit is **absent** — no row. `roster_n` (§3) carries the team size so "5 of 9" is visible.

## 2. Who computes what

| Where | What |
|---|---|
| **Scoring sheet** | Every **per-Respondent** value: Dimension scores (facet map, reverse-keys), Gap and Stance gap, Involvement levels, Coverage gaps, probe Edge markers, safeguards, Levers, learning interest, principle hold, inconsistency flags, the malformed flag. |
| **Dashboard** | Only **team-level** statistics: means, ranges, medians, counts per level, draft norms, `n` — because the Context lens changes which Respondents are in view. Plus lookups that are pure reading: Coverage Edge markers (a 6 on a high-stakes area), N/A↔level pairings, label text. |

One implementation of every scoring rule, in the artifact the Rubric describes. The dashboard never re-derives a per-Respondent number.

## 3. Header grammar

```
family.name.pass
```

- Lowercase; words from `CONTEXT.md`; hyphens inside a segment, dots between segments. No spaces, no punctuation that needs quoting.
- **pass** ∈ `current` · `future-personal` · `future-team` — the glossary's Current score, Future score × Personal stance, Future score × Team stance. Families that are not per-pass omit the segment.
- Item and probe IDs keep their bank codes (`C1`, `FC1`, `P2`) — the ID is the stable name of an item whose text is the key in Forms.

Order is a documented convention — *who → context → results → evidence* — not part of the contract. The loader ignores it.

### Key table

The `name` segment of every header. Slugs, not numbers: an ordering is not an identity.

| Family | Keys |
|---|---|
| `<dim>` | `comfort` `trust` `fluency` `guardrails` `concern` `autonomy` `craft-values` |
| `<area>` | `requirements` `architecture` `production-code` `tests` `code-review` `debugging` `documentation` `refactoring` · `ci-cd` `infrastructure` `incident-response` `monitoring` · `data-migrations` `security-review` `dependency-upgrades` · `estimates` `stakeholder-comms` `learning` `meeting-notes` |
| `<safeguard>` | `read-myself` `another-person` `tests` `rollback` `schema-check` `small-blast-radius` `security-scan` |
| `<tool>` | `copilot` `copilot-studio` `m365-copilot` `azure-ai-foundry` `other-tool` |
| `<probe>` | `P1` (Comfort, low) `P2` (Trust) `P3` (Autonomy) `P4` (Concern) `P5` (Craft values) |
| `<id>` | current: `C1–C3 T1–T3 F1–F3 G1–G6 N1–N5 A1–A3 V1–V3` · future: `FC1–FC3 FT1–FT3 FF1–FF3 FG1–FG5 FN1–FN5 FA1–FA3 FV1–FV3` |

`tests` is both an area and a safeguard; the family segment disambiguates. The six **high-stakes areas** (level 6 raises an Edge marker) are `code-review` `ci-cd` `infrastructure` `incident-response` `data-migrations` `security-review`.

## 4. Values

- **Numbers everywhere.** Items 1–5, levels 1–6, tools 1–4, booleans 0/1. The dashboard and the Rubric own the label tables; the file carries none.
- **Scores at full precision.** Score, gap and stance-gap cells stay in **General** number format in the sheet — Excel exports numbers *as displayed*, and a 1-dp cell would ship a rounded Gap ([`scoring-rules.md` §2.4](scoring-rules.md)). The dashboard rounds to 1 dp for display only.
- **Three empty-looking tokens, three meanings:**

| Token | Means | Where |
|---|---|---|
| `NA` | *Not applicable* — "I don't do this work"; a Coverage gap with a non-numeric side; a Lever that cannot be computed | `area`, `area-gap`, `lever` |
| `#N/A` | *Malformed* — a Dimension score (and its gaps) that could not be computed because an item was blank | `dimension`, `gap` |
| *(empty)* | *Nothing* — a blank raw item, i.e. the defect that produced a `#N/A` | `item` only |

The loader distinguishes all three by name. `0` is never used to mean "none" in a level or score column.

## 5. Flags

| Column | Value |
|---|---|
| `flag.malformed` | `0`, or the blank item IDs joined with `;` (e.g. `T2;N4`). Every Dimension touching a listed item reads `#N/A`. |
| `flag.inconsistent-<pass>` | `1` when `read-myself` is ticked **alongside** another safeguard in that asking. Flagged, never resolved by rule; Levers read `NA` when current or future-personal is inconsistent. |
| `flag.hold` | `1` when `read-myself` is ticked in future-personal and that answer is consistent — the *principle hold*. |

## 6. File rules

- **Save type:** Excel *"CSV UTF-8 (comma delimited)"* — the only save type that preserves accented names. Writes a BOM; the loader strips it.
- **Delimiter:** comma by instruction; the loader also accepts `;` (Windows locales with a `;` list separator write it regardless of save type), sniffed from the header row.
- **Line ends:** whatever Excel writes (CRLF). The loader accepts either.
- **Version:** `schema` = `1` on every row. The loader refuses any other value with a message naming the version it expected.
- **Location:** real exports live outside this repository (a local folder or the team's SharePoint). `scoring/scored-sample.csv` is the only CSV committed.

## 7. What this hands downstream

- **[#15](https://github.com/AndrewGodlewsky/AI-Dev-Survey/issues/15) Scoring sheet** — the scored sheet's header row is the header above, verbatim; score/gap cells in General format; `roster_n` from one input cell; `flag.malformed` via a `TEXTJOIN` over blank checks; probe Edge markers as `--(answer>=4)`; Levers with the inconsistency exclusion; save instructions name "CSV UTF-8 (comma delimited)".
- **[#16](https://github.com/AndrewGodlewsky/AI-Dev-Survey/issues/16) Dashboard** — loader: file-picker/drag-drop, strip BOM, sniff delimiter, resolve by header, check `schema`, treat `NA` / `#N/A` / empty as three states; compute team statistics only; derive Coverage Edge markers and N/A↔level flags from the pass columns. Develop against `scored-sample.csv`.
- **[#14](https://github.com/AndrewGodlewsky/AI-Dev-Survey/issues/14) Rubric** — owns the label tables the file deliberately omits.
- **[#17](https://github.com/AndrewGodlewsky/AI-Dev-Survey/issues/17) How to read the results** — "the CSV never travels upward" is a process rule to state, not a technical one.
