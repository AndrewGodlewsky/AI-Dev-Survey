AI-Dev-Survey · runbook

From a folder of files to a team picture on screen

Ten steps, in order: build the survey in Microsoft Forms, run it, and turn the responses into the dashboard. Nothing here needs a decision — every choice was made in the repo's tickets; this page just walks the route.

Overview

The whole pipeline is five hand-offs. Each box is a file or an app you will touch; the highlighted ones are yours.

survey/SURVEY.md→ Microsoft Forms→ responses .xlsx→ scoring/scoring.xlsx→ scored .csv→ dashboard/index.html→ Team overview PDF

What you need

  • A Microsoft Forms account in your organisation (the form must record names, so it has to be an org-internal form).
  • Excel desktop, 2019 or Microsoft 365. The scoring sheet uses TEXTJOIN and AGGREGATE; Excel 2016 shows #NAME?. Excel on the web is fine for viewing, but do the paste and the CSV save in desktop Excel.
  • A current browser (Edge or Chrome) for the dashboard. It runs from disk — nothing is uploaded anywhere.
  • About 90 minutes to build the form once, then 35–40 minutes per person to answer it, then about 15 minutes to score and load the results.
Careful

Responses are named, by decision. Two rules follow from that and come up again below: the Forms export and the scored CSV are personal data and live outside the repository; and the manager gets the Team overview as a PDF, never a file with rows in it.

Part A

Set up

1

Get the files

5 minutes · once

  1. Clone or download the repository (AndrewGodlewsky/AI-Dev-Survey) somewhere you can open files from — Desktop or Documents is fine. It works from a synced OneDrive folder, but Excel is happier with the file downloaded locally rather than "online-only".
  2. You will only ever open four things:
    • survey/SURVEY.md — the exact text of the form, section by section, with a build checklist at the end.
    • scoring/scoring.xlsx — the scoring sheet. Formulas only, no macros, so Excel will not ask you to "enable content".
    • dashboard/index.html — the dashboard. One file; double-click it.
    • docs/HOW-TO-READ.md — the one-page guide to what the numbers mean. Share it with the team alongside the results.
  3. Open survey/SURVEY.md in something that renders Markdown tables (VS Code preview, GitHub, or Typora). You will be copying from it for the next hour, so a split screen with Forms is worth setting up.
2

Build the form in Microsoft Forms

60–90 minutes · once · SURVEY.md is the source; its Appendix A is the same checklist in short form

The form has 11 sections and 15 questions. Every Likert statement counts against Forms' 200-question limit; this survey uses 152. Build it top to bottom, in the order the file gives — the order is the fatigue design.

  1. Create the form. forms.microsoft.com → New Form. Title and description: copy the two blocks under Form title and description in SURVEY.md. The description is the only intro respondents see — it carries the named-responses statement, so paste all of it.
  2. Settings first (⋯ top-right → Settings):
    • Only people in my organization can respond → tick Record name and One response per person. Anonymous mode empties the name column, and the name is how the dashboard joins everything.
    • Shuffle questions: off. Show progress bar: on.
    • Set an end date about two weeks out. Customize the thank-you message with the text at the end of the survey file.
  3. For each of the 11 sections: Add new → Section. Paste the section title and description. Sections 3, 7 and 10 (the Coverage grids) share one long description block — it holds the level meanings and the per-area examples; paste it in full each time, changing only the first sentence as the file shows.
  4. For each Likert question (Q1–Q5, Q7–Q9, Q11–Q13): Add new → Likert.
    • Paste the Title (and Subtitle where given — the ⋯ on the question → Subtitle).
    • Options = the scale's labels, verbatim from the scale table at the top of the file, in order — including the leading 1 –, 2 – … numbers. The Coverage grids use the 7-option Involvement scale with N/A – I don't do this work last.
    • Statements = the rows of the question's table, one per line, in the order given. Forms starts a Likert with three placeholder statements — replace them, don't leave blanks. Do not paste the ID column.
    • Toggle Required on.
  5. For each Choice question (Q6, Q10, Q14, Q15): Add new → Choice. Paste the title; add the seven options verbatim; ⋯ → Multiple answers on; no "Other" option. Required on — except Q15, which is deliberately optional.
  6. Preview (top-right) and click through every section once. You are checking three things: every statement is present, no statement text is repeated anywhere in the form, and the option labels start with their number. The scoring sheet matches columns by that exact text.
Check

Count the statements: 5 + 9 + 19 + 9 + 8 + 15 + 15 + 19 + 15 + 15 + 19 = 148 Likert rows, plus 4 Choice questions. If Forms tells you the form is at its question limit, a section was pasted twice.

Careful

If you need to reword anything, change it in three places: the form, survey/SURVEY.md, and column F of the Items sheet in scoring.xlsx. The statement text is the key that links a Forms column to a score — a wording change in only one place silently drops that column.

3

Pre-flight checks with a throwaway form

20 minutes · once · confirms four things the design assumes about how Forms exports

Four behaviours were verified by reading Microsoft's documentation, not by doing. One of them is load-bearing: the scoring treats a blank answer as a broken export, which is only true if Required actually stops a respondent submitting with one grid row unanswered.

  1. Make a separate 3-question form (don't test on the real one — you can't delete a single test response later): one Likert with three statements using the Behaviour scale (1 – Never … 5 – Always), Required; one Likert with two statements using the Involvement scale; one Choice question with Multiple answers on and the seven Safeguard options.
  2. Submit it twice: once fully answered; once trying to leave one Likert row blank.
  3. Responses → Open in Excel. Look at the workbook and tick off:
    • Required per statement — the second submission was refused until every row had an answer. If it went through with a blank, the scoring sheet's "malformed" flag will do real work; nothing else changes.
    • Labels export in full — cells read 4 – Often and N/A – I don't do this work, number and all.
    • One column per statement, headed by the statement text alone (not the question title).
    • Multi-select lands in one cell as the option texts joined by a separator. Whichever separator it is, the scoring sheet copes — it searches for each option's text rather than splitting.
  4. Delete the throwaway form.
4

Pilot with one or two people

One day · ticket #18 — the last open item on the project map

  1. Ask one or two colleagues to take the real form and note the time per section (the progress bar makes section boundaries visible). The design budget is 35–40 minutes.
  2. Ask them for anything that made them stop and think: an ambiguous statement, a grid description they skipped, a scale that didn't fit. That is the only free-text feedback the survey ever collects — it has no free-text questions of its own.
  3. Run Part B (steps 6–9) on the pilot responses end to end. You are looking for: a header that failed to match (a score reads #N/A for everyone), a scale label that didn't convert (a #VALUE!), or the dashboard refusing the file.
  4. Fix wording in the three places from step 2. If a pilot respondent's answers should not be in the real results, Forms → Responses → ⋯ → Delete all responses before the team round; there is no per-person delete.
Check

After the pilot the dashboard's Team overview should render with "2 of 9 submitted" (or whatever your numbers are) and the internal view should show no Pattern flag banner. Two honest respondents should not trip it; if they do, the thresholds on the scoring sheet's Config tab are there to be tuned.

5

Send it to the team

10 minutes

  1. Forms → Collect responses → copy the link. It only works for people in your organisation, which is what you want.
  2. Write the message. Three things to say, because the form's own intro says them too and people read the message first:
    • It takes 35–40 minutes; do it in one sitting; answer on gut reaction.
    • Responses are named and everyone who takes it sees everyone's answers. The manager sees the combined picture only.
    • The deadline (the form's end date).
  3. Note the roster size — the number of people who could answer. You'll type it into the scoring sheet in step 7, and every team number on the dashboard is shown as "n of roster".
Part B

Results → dashboard

Do this once after the deadline (and once during the pilot). Fifteen minutes end to end.

6

Export the responses from Forms

2 minutes

  1. Open the form → Responses tab → Open in Excel. Forms downloads a workbook with one row per person: five built-in columns (Respondent ID, Start time, Completion time, Respondent name, Respondent email address) followed by one column per statement.
  2. If the columns look shuffled relative to the form, that is a known Forms issue — use ⋯ → Sync all responses to a new workbook instead. Either way the scoring sheet matches columns by header text, so order never matters.
  3. Save the workbook outside the repository — your team's SharePoint or a local folder such as Documents\AI-Dev-Survey-results\. It has names in it.
7

Load the responses into the scoring sheet

5 minutes · desktop Excel

The workbook ships filled with eight fake people so you can see what a working sheet looks like. You replace them.

  1. Open scoring/scoring.xlsx. Read the ReadMe sheet once; it is this step in short.
  2. Go to the Responses sheet. Click the corner above row 1 (select all) → Delete. The sample rows must go — a paste only overwrites the cells it covers.
  3. In the Forms export, select all (Ctrl+A) and copy. Back in Responses, click A1 and paste. The header row lands in row 1, people from row 2 down.
  4. Make the calculated sheets the same height as your data. They ship with 8 rows (Values rows 7–14, Pattern and Export rows 2–9). If you have more responses: on each of Values, Pattern and Export, select the last filled row and drag its fill handle down until there is one row per response. If you have fewer: delete the surplus rows on those three sheets. Rows are 1:1 with Responses rows 2, 3, 4 …
  5. On the Config sheet, set roster_n to the team size from step 5. Leave the three threshold cells at their defaults unless the pilot said otherwise.
  6. Excel recalculates as you go. If it doesn't (Formulas → Calculation Options is set to Manual), press Ctrl+Alt+F9.
Check

On the Export sheet: column B lists every respondent's name; there is no #NAME? anywhere (if there is, you are in Excel 2016 or older — use a newer Excel); #N/A appears only in a row where someone left an item blank, and that row's flag.malformed column names the item. flag.flat-… and flag.stance-identical should be 0 for everyone — a 1 means go and ask that person before you share anything, not that the sheet is wrong.

8

Save the scored CSV

2 minutes · this is the one file the dashboard reads

  1. Right-click the Export sheet tab → Move or Copy… → To book: (new book) → tick Create a copy → OK. A new workbook opens containing only the scored values. (Saving a sheet as CSV converts the whole workbook, so copying it out first keeps scoring.xlsx intact.)
  2. In that new workbook: File → Save As → choose the type CSV UTF-8 (Comma delimited) (*.csv). Not plain "CSV (Comma delimited)" — that one loses accented names. Save it next to the Forms export from step 6, outside the repository. Name it something like scored-2026-09.csv.
  3. Close the new workbook without saving again. Close scoring.xlsx; saving it is fine — it now holds your real responses, which is another reason it must stay out of any shared repo.
Careful

Don't open the CSV in Excel afterwards "just to look" and save it — Excel will reformat numbers and dates on the way back out. If you want to look, look in a text editor. The dashboard is the viewer.

9

Open the dashboard and load the CSV

1 minute

  1. Double-click dashboard/index.html. It opens in your browser from disk; there is no server and nothing leaves your machine.
  2. Drag the CSV from step 8 onto the page, or click the file picker. The Team overview appears.
  3. Confirm the header line reads "n of roster submitted" with your numbers, and that the filter row's n = matches.
  4. Look for a banner at the top saying Resolve before exporting. It appears only in the internal view, only when someone's answers follow a pattern the survey's built-in checks don't support. It names who. Have that conversation before step 10; the numbers are untouched either way.

If the page refuses the file, it says why in the load box — see Troubleshooting; the three messages it can give all mean the CSV didn't come out of step 8 the way it should.

10

Read it, then share the right thing with the right people

The team gets the internal view; the manager gets one PDF

  1. For the team — the whole survey group looks at the dashboard together, in the Internal (named) view. Send them docs/HOW-TO-READ.md first; it is one page and explains each screen and what a big Gap, a wide spread, a Personal-vs-Team split and an Edge marker each mean.
  2. Work down the left-hand list — topics are ordered by how much the team disagrees today — and use the Lens to filter by tool. Every team number shows its own n.
  3. For the manager — click Team overview at the top of the list, then the Print / save as PDF button in its banner. That page has no names anywhere: counts per level, means, ranges, medians. Send the PDF.
  4. Never send the CSV, the Forms export, or a screenshot of the internal view upward. Say it out loud in the room: at 5–9 people, even an unnamed distribution is partly guessable by anyone who knows the team — the one-pager states that rather than hiding it.
