AI-Dev-Survey · v2 runbook

From survey text to a dashboard the team can argue with

Build the form once, pilot it, send it, then: drop the export in a folder, run one command, read the results on localhost. No Excel, no installs, no dependencies.

Overview

survey/SURVEY.md→ Microsoft Forms→ the team answers→ .xlsx export → data/→ python app/serve.py→ dashboard on localhost

What you need

  1. A Microsoft Forms account in your organisation (the form must record names, so it has to be an org-internal form).
  2. Python 3 — any recent version; the app uses only the standard library.
  3. A current browser (Edge or Chrome). The dashboard is served on localhost; nothing is uploaded anywhere.
  4. About 90 minutes to build the form once, then about 30 minutes per person to answer it, then about 2 minutes to see results.
Careful

This repository is public and a real Forms export carries every respondent's name and email. Real exports live only in the gitignored data/ folder; a pre-commit guard blocks them from ever being committed. After a fresh clone, re-arm the guard once: git config core.hooksPath .githooks.

Part A

Set up

1

Get the files

5 minutes · once

  1. Clone or download the repository (AndrewGodlewsky/AI-Dev-Survey).
  2. You will only ever open three things:
    • survey/SURVEY.md — the exact text of the form, section by section, with a build checklist at the end (Appendix A).
    • app/serve.py — the app. You run it; you don't edit it.
    • docs/HOW-TO-READ.md — the guide to what the numbers mean. Share it with the team alongside the results.
  3. Open survey/SURVEY.md in something that renders Markdown tables (VS Code preview, GitHub, or Typora). You will be copying from it for the next hour, so a split screen with Forms is worth setting up.
2

Build the form in Microsoft Forms

60–90 minutes · once · SURVEY.md is the source; its Appendix A is the same checklist in short form

  1. Create the form. forms.microsoft.com → New Form. Title and description: copy the two blocks under Form title and description in SURVEY.md. The description is the only intro respondents see — it carries the named-responses statement, so paste all of it.
  2. Settings first (⋯ top-right → Settings):
    • Only people in my organization can respond → tick Record name and One response per person. Anonymous mode empties the name column, and the name is how the app joins everything.
    • Shuffle questions: off. Show progress bar: on.
    • Set an end date about two weeks out. Customize the thank-you message with the text near the end of the survey file.
  3. For each of the 9 sections: Add new → Section. Paste the section title and description. Sections 3 and 7 (the two Coverage passes) share one long description block — it holds the level meanings and the per-area examples; paste it in full both times, changing only the first line as the file shows.
  4. For each Likert question (Q1–Q5, Q7–Q9, Q12–Q13): Add new → Likert.
    • Paste the Title (and Subtitle where given — the ⋯ on the question → Subtitle).
    • Options = the scale's labels, verbatim from the scale table at the top of the file, in order — including the leading 1 –, 2 – … numbers. The Coverage grids use the 7-option Involvement scale with N/A – I don't do this work last.
    • Statements = the rows of the question's table, one per line, in the order given — the order carries deliberate placement, so don't resort it. Do not paste the ID column.
    • Toggle Required on.
  5. For each Choice question (Q6, Q10, Q11, Q14): Add new → Choice. Paste the title; add the eight options verbatim, in the interleaved order given — the same eight texts in the same order all four times; ⋯ → Multiple answers on; no "Other" option. Required on — except Q11, which is deliberately optional.
  6. Preview (top-right) and click through every section once. You are checking three things: every statement is present, no statement text is repeated anywhere in the form, and the option labels start with their number. The app matches columns by that exact text.
Check

Count the statements: 5 + 9 + 19 + 9 + 8 + 13 + 19 + 12 + 12 + 12 = 118 Likert rows, plus 4 Choice questions — 122 answers in all.

Careful

If you need to reword anything, change it in two places: the form and survey/SURVEY.md (the app's items map is built from that file). The statement text is the key that links a Forms column to a score — a wording change in only one place silently drops that column.

3

Pre-flight checks with a throwaway form

20 minutes · once · confirms what the scoring assumes about how Forms exports

One behaviour is load-bearing: the scoring treats a blank answer as a broken export, which is only true if Required actually stops a respondent submitting with one grid row unanswered.

  1. Make a separate 3-question form (don't test on the real one — you can't delete a single test response later): one Likert with three statements using the Behaviour scale, Required; one Likert with two statements using the Involvement scale; one Choice question with Multiple answers on and the eight Safeguard options.
  2. Submit it twice: once fully answered; once trying to leave one Likert row blank.
  3. Responses → Open in Excel. Look at the workbook and tick off:
    • Required per statement — the second submission was refused until every row had an answer. If it went through with a blank, the app's "malformed" flag will do real work; nothing else changes.
    • Labels export in full — cells read 4 – Often and N/A – I don't do this work, number and all.
    • One column per statement, headed by the statement text alone (not the question title).
    • Multi-select lands in one cell as the option texts joined by a separator. Whichever separator it is, the app copes — it searches for each option's text rather than splitting.
  4. Delete the throwaway form.
4

Pilot with one or two people

One day · the last stop before the team round

  1. Ask one or two colleagues to take the real form and note the time per section (the progress bar makes section boundaries visible). The design budget is about 30 minutes.
  2. Ask them for anything that made them stop and think: an ambiguous statement, a grid description they skipped, a scale that didn't fit. That is the only free-text feedback the survey ever collects — it has no free-text questions of its own.
  3. Run Part B (steps 6–7) on the pilot responses end to end. You are looking for: a header that failed to match (a score reads #N/A for everyone), a label that didn't convert, or the app refusing the file.
  4. Watch the v2 watch list from the item-bank tickets: Fluency's two Direction items answered identically, D-G1/D-G5 answered as a pair, and whether the section-6 description is read or skipped.
  5. Fix wording in the two places from step 2. If a pilot respondent's answers should not be in the real results, Forms → Responses → ⋯ → Delete all responses before the team round; there is no per-person delete.
5

Send it to the team

10 minutes

  1. Forms → Collect responses → copy the link. It only works for people in your organisation, which is what you want.
  2. Write the message. Three things to say, because the form's own intro says them too and people read the message first:
    • It takes about 30 minutes; do it in one sitting; answer on gut reaction.
    • Responses are named and everyone who takes it sees everyone's answers. Nothing leaves the team as a file.
    • The deadline (the form's end date).
  3. Note the roster size — the number of people who could answer. Every team number on the dashboard is shown as "n of roster".
Part B

Results → dashboard

Do this once after the deadline (and once during the pilot). Two minutes end to end.

6

Export the responses from Forms

2 minutes

  1. Open the form → Responses tab → Open in Excel. Forms downloads a workbook with one row per person: the built-in columns (ID, times, name, email) followed by one column per statement.
  2. If the columns look shuffled relative to the form, that is a known Forms issue — use ⋯ → Sync all responses to a new workbook instead. Either way the app matches columns by header text, so order never matters.
  3. Save the workbook into the repo's data/ folder. It is gitignored, and the pre-commit guard refuses it even force-added — that folder is where real data is supposed to live, and the only place.
7

Run the app

1 minute · replaces v1's scoring sheet, CSV export and file-drop entirely

  1. In a terminal at the repository root: python app/serve.py
  2. The terminal prints a parse summary (file found, respondents, columns matched) and your browser opens the dashboard at http://localhost:8737/. Ctrl+C stops it.
  3. If data/ holds more than one export, the newest wins and the terminal says which it ignored. With no export at all, the app runs against the committed fake fixture so you can always see a working dashboard.
  4. Want the numbers in a file? The dashboard offers a CSV download of everything it computed (scores, gaps, levels, markers, flags — no raw answers). That file is named data too; treat it like the export.
8

Read it, then share the right thing

The team reads it together; anything that goes further is a screenshot

  1. For the team — look at the dashboard together. It is one page, five questions: Where are we today? What do we want more of? Where would AI do the work? Where do we differ most? What norms would we set? People appear as initials; hover shows the full name. Send docs/HOW-TO-READ.md around first.
  2. Initials are a display choice, not anonymity — at 5–9 people everyone knows who is who, and results are open within the team anyway. Say that out loud once.
  3. Beyond the team — nothing travels as a file. Screenshot the team-level pieces you choose to share, together, and send those. Never the export, never the CSV, never a hover.

Troubleshooting

You seeIt meansDo
Terminal: "no .xlsx found"data/ is empty (and the fixture is missing).Step 6 — save the Forms export into data/.
Terminal: "is not a readable Forms export"The file is corrupt, half-downloaded, or not an .xlsx.Re-download from Forms (Responses → Open in Excel).
Terminal warns about duplicate statement headersTwo questions in the form share the same statement text.Reword one in Forms and in SURVEY.md — the text is the key.
A score reads #N/A for everyone on one DimensionOne of that Dimension's statements didn't match a Forms header — wording differs.Compare the form's statement with SURVEY.md; fix so both match exactly.
#N/A for one person, malformed flag names an itemThat person's answer to that item is blank in the export.Not an app problem. Ask them; if Required wasn't enforced per row (step 3), expect this occasionally.
Dashboard shows a Pattern flag beside someoneTheir answers follow a pattern the reverse-keyed items don't support.Go and ask — it locates a conversation, never a fault. The numbers are untouched.
Names show as "Respondent 1, 2 …"The form was anonymous, so the name column was empty.Step 2 settings — Record name. Responses already collected anonymously can't be recovered.
Browser doesn't openHeadless environment or blocked default browser.Open http://localhost:8737/ yourself; the server is running either way.
